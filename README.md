# MOTION — анализ движения

Мобильное веб-приложение на HTML, CSS и JavaScript. Живая камера, локальный видеофайл и анализ позы работают в браузере; содержимое видео не отправляется на сервер. При первом запуске нужны сеть и доступ к CDN для загрузки MediaPipe Tasks Vision и модели Pose Landmarker Lite.

## Запуск

```sh
python3 -m http.server 4173
```

Откройте `http://localhost:4173` на том же устройстве. Доступ к камере на другом устройстве требует HTTPS (или другой поддерживаемый браузером защищённый контекст).

Выберите камеру или локальный файл, затем в окне настройки выберите упражнение и начните подход. Под селектором показана рекомендация по ракурсу и нужным точкам. Доступны приседания, планка, боковая планка, сгибания рук, выпады, жим вверх, румынская тяга, jumping jacks, ягодичный мостик и подтягивания. Отжиманий в списке нет: соответствующего анализатора в проекте пока нет.

## Тренировочный подход

1. Нажмите «Старт камеры» или «Загрузить видео». До запроса доступа к камере или чтения файла откроется настройка: выберите упражнение, цель или **Свободный режим**. Для повторений предложены 5, 10, 15 и 20; для обеих планок — 15, 30, 45 и 60 секунд. Можно ввести собственное положительное целое число. При смене упражнения цель возвращается к значению по умолчанию.
2. Нажатие **«Начать подход»** сбрасывает результат и запускает источник и анализ. До завершения подхода выбор упражнения заблокирован, чтобы не потерять накопленный результат. Смена камеры или файла результат не обнуляет.
3. В упражнениях на повторения HUD показывает число повторов; в обеих планках — накопленные **секунды корректного удержания**. При заданной цели показаны `X / Y` и шкала прогресса, в свободном режиме — `∞`. HUD и итоги показывают полные секунды с округлением вниз; внутренний результат сохраняет дробную часть.
4. При достижении цели подсчёт и источник останавливаются, звучит один короткий сигнал Web Audio API и открываются итоги. **«Завершить упражнение»** останавливает подход вручную без сигнала. Кнопка доступна также при загрузке, паузе и ошибке источника.
5. Итоги показывают упражнение, повторы или время удержания, цель и отдельно время с начала подхода, включая паузы и ожидание источника. **«Новый подход»** снова открывает настройки с последним источником.

Для обеих планок счёт идёт только между двумя подтверждёнными кадрами корректной формы. Потеря позы или опоры приостанавливает таймер; первый кадр восстановления время не добавляет. При паузе, перемотке, зацикливании и смене источника непрерывность сбрасывается, а накопленное время сохраняется. Интервалы без наблюдения свыше одной секунды не засчитываются. Камера использует разницу монотонных часов, файл — разницу медиавремени ролика; предпросмотр на паузе удержание не увеличивает.

Сигнал создаётся браузером только при достижении цели; предупреждения техники исключительно визуальные и текстовые. Устройство или браузер могут запретить звук без влияния на завершение. Углы и цветовая подсветка проблемных сегментов сейчас доступны только для приседаний; остальные упражнения показывают общий скелет и фактическую рекомендацию своего анализатора.

`showWorkoutResults(result)` получает неизменяемый снимок `{ reason, exerciseId, mode, repCount, activeHoldTime, goal, durationMs }`. Для планок `repCount` равен `null`, `activeHoldTime` — число секунд; для остальных наоборот. `reason` — `goal` или `manual`, `goal` равен `null` в свободном режиме, `durationMs` — полное время подхода в миллисекундах. Снимок хранится в `workout.lastResult` до следующего старта и не записывается на сервер или в постоянное хранилище.

## Фабрика упражнений

`exerciseFactory.js` хранит каталог и создаёт независимый автомат для выбранного ID:

```js
import { createAnalyzer } from './exerciseFactory.js';

let currentAnalyzer = createAnalyzer('squat');
// При изменении выбора до начала подхода:
currentAnalyzer = createAnalyzer('plank');
```

`app.js` передаёт всем анализаторам размер кадра и `null` при потере позы. Планкам передаётся `deltaTime` в секундах, а `JumpingJacksAnalyzer` и `PullUpAnalyzer` — строго возрастающая отметка `performance.now()` в миллисекундах. Для видеофайлов их показатели скорости и синхронизации относятся ко времени воспроизведения, поэтому зависят от его скорости. Ниже описаны интерфейсы и ограничения отдельных автоматов.

## Источники видео

- Нажмите «Старт камеры» для живого изображения или «Загрузить видео», чтобы выбрать файл с устройства. Подходят MP4, WebM и MOV, если их видеокодек поддерживает браузер и операционная система; одно только расширение файла не гарантирует воспроизведение.
- После выбора файла камера останавливается, а ролик декодируется локально. Воспроизведение начинается после загрузки модели; если браузер запретил автозапуск, нажмите **Play**. Панель позволяет поставить видео на паузу, перемотать его и включить **Повтор**. Звук не воспроизводится.
- «Живая камера» освобождает локальный URL файла и снова запрашивает доступ к камере. Обе кнопки работают и во время загрузки источника; запоздавшие запросы камеры и ранее выбранные файлы не заменят актуальный источник.
- Смена файла или возврат к камере внутри одного подхода сохраняют счётчик и сбрасывают только незавершённую попытку или непрерывность удержания. То же происходит при перемотке и переходе на начало при повторе. Если ролик проигрывается заново, упражнения в нём считаются ещё раз. «Стоп камеры» приостанавливает источник, но не завершает подход; для итога используйте кнопку завершения вверху.

На паузе цикл распознавания не работает; первый кадр при загрузке и кадр после перемотки могут анализироваться один раз для обновления скелета. Время для MediaPipe берётся из монотонного `performance.now()` и остаётся строго возрастающим даже при перемотке, повторе и смене источника. Анализ идёт во время воспроизведения: если устройство не успевает, часть кадров и повторов может быть пропущена.

## Анализатор

`analyzer.js` экспортирует `SquatAnalyzer`. На каждом обработанном кадре передавайте ему нормированные landmarks первой позы MediaPipe:

```js
import { SquatAnalyzer } from './analyzer.js';

const analyzer = new SquatAnalyzer({ view: 'auto' });
analyzer.setFrameSize(video.videoWidth, video.videoHeight);
const { repCount, currentPhase, currentErrors, feedbackMessage } = analyzer.update(landmarks);
```

Передавайте `null`, если поза не найдена. Начальная фаза `WAITING` требует исходной стойки; затем доступны `STANDING`, `DESCENDING`, `BOTTOM` и `ASCENDING`. Нижняя точка подтверждается разворотом или паузой. Используется средний угол доступных коленей; при длительной потере позы незавершённый повтор отменяется. `resetTracking()` отменяет незавершённый повтор с сохранением счётчика, `reset()` обнуляет счётчик. `setView('auto' | 'front' | 'side')` задаёт ракурс.

`analyzer.getHighlightedSegments()` возвращает проблемные сегменты последнего обработанного кадра для отрисовки поверх скелета. Красным обозначаются превышение порога наклона корпуса и недостаточная глубина, жёлтым — замечания к положению коленей. Текст предупреждения сохраняется не менее 1,8 секунды, если его не заменяет более приоритетное; цвет скелета отражает текущий кадр.

Измерения приблизительны и зависят от камеры, ракурса и видимости суставов. Пороги заданы как программные ориентиры, а не медицинский диагноз; положение колена впереди носка само по себе не означает опасной техники.

## Анализатор планки

`plankAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Снимайте человека сбоку, по возможности с горизонтально установленной камерой. В кадре должны быть видны плечо, таз, колено, лодыжка и хотя бы локоть или запястье той же стороны.

```js
import { PlankAnalyzer } from './plankAnalyzer.js';

const plank = new PlankAnalyzer();
plank.setFrameSize(video.videoWidth, video.videoHeight);
let previousFrameTime = null;

function analyzePlank(landmarks) {
  const now = performance.now();
  const deltaTime = previousFrameTime === null ? 0 : (now - previousFrameTime) / 1000;
  previousFrameTime = now;
  const { activeHoldTime, isFormCorrect, feedbackMessage } = plank.update(landmarks, deltaTime);
  return { activeHoldTime, isFormCorrect, feedbackMessage };
}

function pauseOrChangeSource() {
  previousFrameTime = null;
  plank.resetTracking(); // сохранить уже засчитанное время
}

function startNewPlank() {
  previousFrameTime = null;
  plank.reset(); // начать с нуля
}
```

В `update` передавайте `null` при потере позы; `deltaTime` — конечное неотрицательное число **секунд**. Время добавляется только между двумя корректными кадрами: первый кадр после ошибки или отсутствия данных не включает паузу. Интервалы без наблюдения дольше одной секунды не засчитываются; для низкой частоты кадров порог можно изменить параметром `new PlankAnalyzer({ maxFrameGapSeconds: 2 })`.

Анализатор использует двумерную проекцию и размеры видео, чтобы нормированные X и Y имели один масштаб. `findAngle` возвращает 0–180°, поэтому направление изгиба таза определяется отдельно по его положению относительно линии плечо–колено; это работает и при зеркалировании. Локоть/запястье и стопа используются для **приблизительной** оценки уровня пола. При отсутствии надёжной опоры таймер приостанавливается. Одной камеры и landmarks недостаточно для безошибочного определения контакта с полом: перспективные искажения, перекрытие суставов и наклон камеры могут привести к ошибке.

## Анализатор боковой планки

`sidePlankAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Камера смотрит на спортсмена спереди; желательно установить её горизонтально. Для центров оси нужны оба плеча, обе точки таза и обе лодыжки. Опорная сторона определяется по нижнему плечу. Также должны быть видны локоть или запястье опорной руки и лодыжки; видимые пятки и носки уточняют приблизительную линию пола.

```js
import { SidePlankAnalyzer } from './sidePlankAnalyzer.js';

const sidePlank = new SidePlankAnalyzer({ maxFrameGapSeconds: 1 });
sidePlank.setFrameSize(video.videoWidth, video.videoHeight); // после загрузки видео
let previousFrameTime = null;

function analyzeSidePlank(landmarks) {
  const now = performance.now();
  const deltaTime = previousFrameTime === null ? 0 : (now - previousFrameTime) / 1000;
  previousFrameTime = now;
  return sidePlank.update(landmarks, deltaTime);
}

function pauseOrChangeSource() {
  previousFrameTime = null;
  sidePlank.resetTracking(); // сохранить накопленное время
}

function startNewSidePlank() {
  previousFrameTime = null;
  sidePlank.reset(); // начать с нуля
}
```

`update` возвращает `{ activeHoldTime, isFormCorrect, feedbackMessage }`; время и `deltaTime` указаны в секундах. Передавайте `null` при потере позы. Время добавляется только между двумя корректными кадрами одной опорной стороны; первый кадр после ошибки, смены стороны или потери данных не включает паузу. Интервалы длиннее `maxFrameGapSeconds` не засчитываются.

Ось рассчитывается в плоскости изображения по серединам плеч, таза и лодыжек. Обычный угол трёх точек не превышает 180°, поэтому направление изгиба определяется относительно линии плечи–лодыжки: провисанию соответствуют значения ниже 180°, поднятому тазу — выше 180°. Включительный допустимый диапазон — **165–185°**. При угле ниже 160° выводится предупреждение о провисании; при 160–165° таймер также на паузе, но порог сильного провисания не заявляется. Значение выше 185° тоже останавливает таймер.

Линия плеч сравнивается с перпендикуляром к приблизительной линии пола. При отклонении **более 20°** выводится предупреждение и таймер останавливается. Для подтверждения формы нужны конечные координаты Z обоих плеч: без них 2D-проекция может показать видимый наклон, но не может подтвердить отсутствие скручивания в глубину, поэтому таймер на паузе. Z MediaPipe — приблизительная оценка, а не точное пространственное измерение; скручивание может остаться незамеченным или определиться ошибочно.

Пол оценивается по проекции локтя/запястья опорной руки и доступной точки стопы. При лежании у пола, отсутствии подходящих опор или неясной высоте корпуса таймер приостанавливается. Видимые колени используются для отбраковки явно ненадёжной линии пола, но отдельный порог сгибания коленей не задаётся. Контакт с полом, истинная ориентация тела и безопасность упражнения по этим landmarks достоверно не определяются: оценка зависит от перспективы, ракурса и качества модели и требует проверки на реальном видео.

## Анализатор сгибаний рук

`bicepCurlAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Снимайте человека сбоку или в три четверти так, чтобы были видны плечо, локоть, запястье и таз одной стороны. Для автоматического определения направления желательно видеть также нос и оба уха либо нос, ухо и противоположный глаз.

```js
import { BicepCurlAnalyzer } from './bicepCurlAnalyzer.js';

const curls = new BicepCurlAnalyzer({ side: 'auto', facingDirection: 'auto' });
curls.setFrameSize(video.videoWidth, video.videoHeight);

// Вызывать на каждом обработанном кадре; при отсутствии позы передать null.
const { repCount, currentPhase, currentErrors, feedbackMessage } = curls.update(landmarks);

// При перемотке, смене источника или паузе:
curls.resetTracking(); // отменить незавершённое движение, сохранить счётчик
// При начале нового подхода:
curls.reset(); // обнулить счётчик и состояние
```

`side: 'auto'` выбирает одну руку: сначала предпочитает сторону с видимым тазом, затем сравнивает минимальную уверенность видимых суставов. Выбор фиксируется до длительной потери руки, чтобы движения двух рук не смешивались. Можно явно задать анатомическую сторону: `side: 'left'` или `side: 'right'`; изменить её позже — `curls.setSide(...)`. После десяти кадров без выбранной руки незавершённая попытка отменяется, но счётчик сохраняется.

`facingDirection: 'auto'` приблизительно определяет направление по носу и ушам (если видно только одно ухо, используется также противоположный глаз). Если лицо закрыто или ракурс недостаточно выраженный, направление можно задать явно: `facingDirection: 'left'` или `'right'`; для изменения используйте `curls.setFacingDirection(...)`. Изменение руки или направления отменяет незавершённое движение, не обнуляя счётчик. Это **направление в исходных координатах кадра, переданного MediaPipe**, а не обязательно в зеркальном отображении на экране. Автоматическая проверка наклона назад требует уверенно определённого направления и внизу, и на текущем кадре подъёма; при неизвестном или изменившемся направлении соответствующая ошибка не заявляется, даже если ранее в этом повторе была замечена раскачка. Корпус сравнивается с его наклоном в начале подъёма, а не просто с вертикалью.

Фазы: `WAITING`, `DOWN` (>155°), `CURLING`, `PEAK` (≤45°) и `LOWERING`. Повтор засчитывается по возвращении в `DOWN`. При неполном подъёме выше 55° локальный минимум подтверждается разворотом на 3° и выдаётся предупреждение, но завершённый повтор всё равно учитывается. Движение менее 10° не считается повтором, чтобы отсечь дрожание. Начало подъёма при угле менее 145° предупреждает о неполном разгибании. Диапазон выше 45° до 55° включительно не помечается ошибкой недожима, но даётся рекомендация достичь целевой верхней точки.

`currentErrors` содержит текстовые описания ошибок; для сравнения можно использовать экспортируемые константы `BICEP_ERROR.SHORT_BOTTOM`, `BICEP_ERROR.SHORT_TOP`, `BICEP_ERROR.ELBOW_DRIFT` и `BICEP_ERROR.BACK_SWAY`. Ошибки накапливаются в рамках текущего движения и возвращаются в кадре завершения; `feedbackMessage` содержит текстовую подсказку. Угол таз–плечо–локоть >25° отмечает **любое** смещение локтя относительно корпуса: этот неориентированный угол сам по себе не показывает, вперёд оно или назад. При отсутствии тазовой точки повтор можно посчитать по руке, но проверка корпуса и локтя недоступна.

Размеры кадра нужны для единого масштаба осей. При наличии Z у всех точек конкретного угла используется 3D, иначе 2D; наклон и направление корпуса оцениваются по изображению. Результаты приблизительны и зависят от качества landmarks, угла камеры, видимости человека и перспективных искажений; особенно ненадёжен фронтальный ракурс.

## Анализатор выпадов

`lungeAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Камеру следует расположить сбоку или в три четверти (примерно 45–90° к направлению движения), желательно горизонтально. В кадре нужны таз, колени и лодыжки обеих ног; для проверки корпуса и положения колена также должны быть видны плечо и носок передней стопы.

```js
import { LungeAnalyzer } from './lungeAnalyzer.js';

const lunges = new LungeAnalyzer({ facingDirection: 'auto' });
lunges.setFrameSize(video.videoWidth, video.videoHeight);

// На каждом обработанном кадре; если поза не найдена, передать null.
const { repCount, currentPhase, currentErrors, feedbackMessage } = lunges.update(landmarks);

lunges.resetTracking(); // прервать незавершённый выпад, сохранив повторы
lunges.reset(); // начать новый подход с нуля
```

`WAITING` ожидает, пока оба колена выпрямятся (более 160°). Затем доступны `STANDING`, `LUNGING`, `BOTTOM` и `ASCENDING`. Повтор засчитывается после подтверждения нижней точки и выпрямления обеих ног; сводить стопы вместе не обязательно, поэтому поддерживается и фиксированная разножка. Недостаточная глубина (>105° в нижней точке) не отменяет повтор, но сопровождается предупреждением. Небольшая амплитуда выше 150° не засчитывается; разворот на 3° или короткая пауза подтверждают нижнюю точку.

Передняя нога определяется по разнесению лодыжек и направлению носков и фиксируется до конца повтора. Если направление стоп неизвестно или противоречиво, настройте `facingDirection: 'left'` или `'right'` либо вызовите `setFacingDirection(...)`. Направление задаётся в **координатах исходного кадра MediaPipe**, а не зеркального preview. Если ведущую ногу нельзя определить, незавершённый выпад не засчитывается. При длительной потере любой ноги (10 кадров) незавершённый повтор отменяется, но счётчик сохраняется.

Проверка колена использует допуск 5% длины ноги в проекции, а не считает любое пересечение носка ошибкой. Положение колена за носком само по себе не является медицинским диагнозом или доказательством опасной техники. При отсутствии носка передней стопы проверка колена недоступна; при отсутствии плеча недоступна оценка корпуса. Коды ошибок экспортируются через `LUNGE_ERROR`.

Высота заднего колена приблизительно оценивается по линии между двумя видимыми носками. Это только проекция предполагаемого пола: одно изображение не доказывает ни контакт стоп с полом, ни отсутствие удара коленом. Угол переднего и заднего колена рассчитывается в 3D при наличии Z всех трёх точек, иначе в 2D; наклон корпуса и положение стоп оцениваются в плоскости изображения. Результат зависит от ракурса, перспективы и качества landmarks и требует проверки на реальном видео.

## Анализатор жима стоя

`overheadPressAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Камеру можно расположить спереди или сбоку, желательно горизонтально; для подсчёта и оценки симметрии должны быть видны плечи, локти и запястья **обеих** рук. Таз необходим для оценки высоты кистей и отклонения корпуса. По этим точкам нельзя надёжно отличить положение стоя от сидения.

```js
import { OverheadPressAnalyzer } from './overheadPressAnalyzer.js';

const press = new OverheadPressAnalyzer({ view: 'auto', facingDirection: 'auto' });
press.setFrameSize(video.videoWidth, video.videoHeight);

// На каждом обработанном кадре; при отсутствии позы передать null.
const { repCount, currentPhase, currentErrors, feedbackMessage } = press.update(landmarks);

press.resetTracking(); // отменить незавершённый жим, сохранив счётчик
press.reset(); // начать новый подход с нуля
```

`WAITING` ожидает исходное положение: оба локтя в диапазоне 60–80°, кисти примерно у плеч или подбородка. Дальше доступны `START`, `PRESSING`, `TOP`, `LOCKOUT` и `LOWERING`. В `LOCKOUT` оба локтя должны одновременно превышать 165°, а обе кисти — находиться над плечами с запасом более длины плеча и, если нос видим, также заметно выше носа. Без точки макушки это лишь приближённая проверка положения над головой. После возврата в `START` засчитывается и завершённый частичный жим; чтобы отсечь шум, требуется разгибание не менее 10° и заметный подъём обеих кистей.

При определённой верхней точке локтевой угол ниже 160° выдаёт предупреждение о недожиме. Углы 160–165° не являются этим недожимом, но не образуют `LOCKOUT`. В качестве верхней точки используется наибольшая общая высота кистей; отдельное `TOP` позволяет подтвердить разворот или паузу, не объявляя неполный жим фиксацией. Если обе руки не видны, анализ приостанавливается; после 10 таких кадров незавершённый жим отменяется без потери счётчика.

Асимметрия отмечается при разнице локтевых углов более 15° **или** разнице высот кистей более 15% среднего доступного расстояния плечо–таз в проекции. Если таз не виден, углы и повторы всё ещё можно проверять, но оценка разницы высот недоступна. Значения ошибок экспортируются через `OVERHEAD_ERROR`.

Для проверки отклонения назад выберите `view: 'side'` или оставьте `view: 'auto'`; в виде анфас эта проверка недоступна. Ракурс и направление примерно определяются автоматически, а при необходимости задаются через `setView('side')` и `setFacingDirection('left' | 'right')`. Направление относится к **исходному кадру MediaPipe**, не обязательно к зеркальному preview. Проверка сравнивает линию плечо–таз со стартовой позицией и отмечает отклонение назад более 15° во время подъёма. Если направление или исходное положение неизвестно, соответствующая ошибка не заявляется. Плечо и таз не показывают изгиб позвоночника: это приблизительная оценка наклона корпуса, а не измерение прогиба поясницы или медицинский диагноз.

Углы обеих рук вычисляются в 3D только при наличии Z у всех шести суставов, иначе обе руки сравниваются в 2D. При смене размерности незавершённый жим отменяется, а счётчик сохраняется; высота кистей, ракурс и наклон корпуса определяются по изображению. Результат зависит от перспективы, видимости landmarks и качества камеры и требует проверки на реальном видео.

## Анализатор румынской тяги

`deadliftAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Камеру необходимо установить строго сбоку, желательно горизонтально. Для анализа нужны видимые ухо, плечо, таз, колено и лодыжка **одной стороны**. В стандартной схеме MediaPipe нет отдельной точки шеи, поэтому используется ухо. Автовыбор фиксирует сторону на время попытки, не смешивая суставы разных сторон.

```js
import { DeadliftAnalyzer, DEADLIFT_ERROR } from './deadliftAnalyzer.js';

const deadlift = new DeadliftAnalyzer({ side: 'auto', facingDirection: 'auto' });
deadlift.setFrameSize(video.videoWidth, video.videoHeight); // после загрузки видео

// Вызывайте на каждом обработанном кадре; при потере позы передавайте null.
const { repCount, currentPhase, currentErrors, feedbackMessage, spineAssessment, hipInitiation } =
  deadlift.update(landmarks);

if (currentErrors.includes(DEADLIFT_ERROR.KNEE_BEND)) {
  // Показать предупреждение о чрезмерном сгибании колена.
}

deadlift.resetTracking(); // отменить попытку, сохранив уже засчитанные повторы
deadlift.reset(); // начать подход с нуля
```

**Округление позвоночника не определяется этим модулем.** Плечо и таз задают только отрезок, а положение уха зависит в том числе от головы и шеи. `spineAssessment` всегда равно `'unavailable'`; отсутствие предупреждений не означает ровную или безопасную спину. Если положение уха относительно линии таз–плечо изменилось от стартового более чем на 20°, выводится только нейтральная подсказка о положении головы, а не диагноз и не красный алерт о спине. Стартовая поза не может автоматически подтверждаться как нейтральная. Используйте профессиональную оценку техники; при боли прекратите упражнение и обратитесь за консультацией.

В `WAITING` анализатор ждёт стартовую стойку: наклон корпуса от −10° до 20° относительно вертикали и колено в диапазоне 150–165°. Далее доступны `START`, `HINGING`, `BOTTOM` и `RISING`. Нижняя точка может подтверждаться коротким плато; при развороте на 3° начинается `RISING`. После возврата в стойку повтор учитывается, если отведение таза было замечено и изменение наклона составило не менее 10°. Максимум 60–80° — заданный ориентир, а не универсальный критерий безопасности; меньшая завершённая амплитуда учитывается с замечанием, без призыва принудительно наклоняться глубже. Наклон более 80° отмечается уже в текущем кадре.

Отведение таза измеряется относительно лодыжки; порог заметного смещения — 4% стартовой длины ноги в проекции. `hipInitiation` равен `'pending'` до движения, `'observed'`, если таз пересёк порог до заметного изменения колена или наклона, и `'uncertain'`, если порядок не подтверждён или оба порога достигнуты в одном кадре. Это наблюдение с конечной частотой кадров, а не доказательство точного порядка движений. Возврат таза использует гистерезис: нужен разворот не менее 2% длины ноги и возврат в пределах 4% длины ноги от стартовой проекции.

Если коленный угол строго меньше 130°, предупреждение появляется сразу; относительно стартового угла отдельно отмечается изменение строго более 5°, а выход за 150–165° показывается во время отслеживания. Ошибки текущего кадра возвращаются в `currentErrors`; в кадре завершения туда также попадают замечания, замеченные за попытку. Пороги — программные ориентиры, а не медицинские выводы.

Направление приблизительно определяется по носу и обоим ушам либо по носу, одному уху и противоположному глазу. Если лицо плохо видно, задайте `facingDirection: 'left'` или `'right'`; это направление в **исходном кадре MediaPipe**, не обязательно в зеркальном preview. При потере уха, направления, нужных суставов или смене выбранной стороны незавершённая попытка отменяется без потери счётчика; `hipInitiation` тогда равно `'unavailable'`. При видимости обеих сторон явно неподходящий ракурс отклоняется, но по одной видимой стороне строго боковую съёмку нельзя подтвердить автоматически.

Измерения выполнены в 2D-проекции с учётом размеров кадра и игнорируют Z. При перекрытиях, повороте камеры, движении стоп и ошибках MediaPipe результаты могут быть неверными; синтетические тесты не заменяют проверки на реальном видео или оценки специалистом.

## Анализатор jumping jacks

`jumpingJacksAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Снимайте человека в полный рост строго спереди. Для фаз нужны плечи (11/12), локти (13/14), кисти (15/16), таз (23/24) и лодыжки (27/28). Для проверки высоты кистей нужен хотя бы один глаз (2 или 5). Таз и локти дополнительно необходимы, чтобы оценить направление рук относительно корпуса.

```js
import { JumpingJacksAnalyzer, JACKS_ERROR } from './jumpingJacksAnalyzer.js';

const jacks = new JumpingJacksAnalyzer({ maxFrameGapMs: 1000 });
jacks.setFrameSize(video.videoWidth, video.videoHeight); // после загрузки видео

// Используйте ту же строго возрастающую отметку performance.now(),
// которая передана в poseLandmarker.detectForVideo(video, timestampMs).
const result = jacks.update(landmarks, timestampMs); // при потере позы: null
const { repCount, currentPhase, currentErrors, feedbackMessage,
  cadence, synchronizationDelayMs, eyeReference } = result;

if (currentErrors.includes(JACKS_ERROR.LAZY_ARMS)) {
  // Показать текстовое предупреждение.
}

const currentCadence = jacks.getCadence(); // можно обновлять и на паузе без детекции
jacks.resetTracking(); // отменить незавершённый цикл, сохранив счёт и время подхода
jacks.reset(); // начать новый подход с нуля
```

`CLOSED` требует расстояния между лодыжками строго меньше горизонтальной ширины плеч, а также углов плечо–локоть и плечо–кисть к линии плечо–таз строго менее 30°; кисти должны быть около бёдер. `OPEN` требует в одном кадре расстояния X между лодыжками строго более 1,5 ширины плеч, положения обоих локтей выше плеч, кистей выше локтей и уровня глаз, а также горизонтального расстояния между кистями не более ширины плеч. Помимо этих фаз есть `WAITING`, `OPENING` и `CLOSING`. Засчитывается только полный `CLOSED → OPEN → CLOSED`: частичные попытки не увеличивают счётчик.

Когда руки не достигли верха, показывается «Поднимайте руки полностью над головой», а если ноги не достигли заданной ширины — «Прыгайте шире». Если обе руки поднимались только по отдельности, они отмечаются как несинхронные; если кисти наверху, но слишком далеко друг от друга, предлагается свести их. Отдельное сообщение появляется, когда нужные положения рук и ног наблюдались раздельно, но совместный `OPEN` не был зафиксирован. При малом шевелении рядом со стартом попытка не считается, чтобы не выдавать лишние предупреждения.

`synchronizationDelayMs` — разница между временами первых кадров с открытыми руками и с открытыми ногами внутри попытки; при разнице строго более 300 мс выводится подсказка о синхронности. Один кадр может одновременно подтвердить оба условия. Это оценка по дискретным кадрам, а не точный момент движения: частота кадров и шум landmarks влияют на результат.

`cadence` — среднее число **полных** повторов в минуту: `repCount × 60000 / прошедшие_миллисекунды` с первого `update()` после `reset()`. Время ожидания и остановки входят в среднее; `getCadence()` позволяет пересчитать его без обработки видеокадра. Можно передать `timestampMs` явно: это неотрицательные строго возрастающие миллисекунды одного источника, например `performance.now()`. `resetTracking()` сохраняет исходную отметку и последнюю отметку кадра, поэтому после паузы используйте тот же монотонный источник; новый подход или смена источника времени требует `reset()`.

При потере любого необходимого сустава или обоих глаз незавершённый цикл отменяется, счёт и время подхода сохраняются. Один видимый глаз используется приблизительно; `eyeReference` равно `'single'`, и ограничение сохраняется до завершения этой попытки. По умолчанию пропуск между кадрами более секунды также отменяет незавершённый цикл; порог меняется через `maxFrameGapMs`.

Положения проверяются в 2D-проекции с учётом размеров видеокадра; узкий профиль отбраковывается, но строгий ракурс спереди автоматически не гарантируется. По указанным точкам нельзя достоверно установить отрыв стоп от пола: шаги с теми же позами тоже могут быть засчитаны. Реальное видео пока не проверялось.

## Анализатор ягодичного мостика

`gluteBridgeAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Установите камеру строго сбоку, горизонтально и на уровне пола; плечо (11/12), таз (23/24), колено (25/26) и лодыжка (27/28) одной стороны должны быть видны целиком. Сторона в режиме `auto` фиксируется на время попытки; её нельзя незаметно заменить противоположной.

```js
import { GluteBridgeAnalyzer, GLUTE_ERROR } from './gluteBridgeAnalyzer.js';

const bridge = new GluteBridgeAnalyzer({ side: 'auto' }); // также 'left' или 'right'
bridge.setFrameSize(video.videoWidth, video.videoHeight); // после загрузки видео, до update

// Вызывайте для каждого обработанного кадра; при потере позы передавайте null.
const { repCount, currentPhase, currentErrors, feedbackMessage, floorContact, spineAssessment } =
  bridge.update(landmarks);

if (currentErrors.includes(GLUTE_ERROR.HIP_HIGH)) {
  // Показать нейтральную подсказку о высоком положении таза.
}

bridge.resetTracking(); // отменить незавершённую попытку, сохранив счёт
bridge.reset(); // начать подход с нуля
```

`BOTTOM` определяется **только по углу** плечо–таз–колено 100–120° включительно: это не подтверждение лежания или контакта с полом. `PEAK` — наблюдаемый ориентированный угол 170–195° включительно, в том числе во время опускания. Значения выше 180° получаются с учётом положения таза относительно прямой плечо–колено; формула работает и при зеркалировании изображения. Остальные фазы: `WAITING`, `LIFTING`, `TOP` (подтверждённая верхняя точка вне диапазона `PEAK`) и `LOWERING`.

Повтор засчитывается после наблюдения `PEAK` и возвращения в `BOTTOM`; неполные подъёмы не считаются. Подъём выше 195° после достижения `PEAK` засчитывается с предупреждением о высоком положении таза, без диагноза поясницы. Если заданная верхняя зона прошла **между** кадрами и ни разу не была видна, повтор не засчитывается по предположению. Дополнительно для отсеивания мелких движений нужны подъём таза относительно плеча не менее 10% исходной длины отрезка плечо–таз в проекции, изменение угла не менее 10° и разворот высоты от максимума не менее 4% этой длины. Точно возвращаться к исходной высоте не требуется: нижняя фаза по-прежнему определяется по углу.

При подтверждённой верхней точке ниже 160° показывается «Поднимите таз выше, сожмите ягодицы»; при 160–170° верхний диапазон ещё не достигнут, но это отдельное замечание, не предупреждение ниже 160°. Плато высоты в шести кадрах или разворот подтверждает верхнюю точку приблизительно; подсказка «сожмите ягодицы» — инструкция, а не измерение их активации. Коленный угол таз–колено–лодыжка ниже 70° или выше 110° сопровождается подсказкой проверить положение стоп; границы 70° и 110° допустимы. В `PEAK` проверяется текущий кадр, а итоговый коленный угол и угол таза берутся из одного кадра максимальной наблюдаемой высоты таза относительно плеча.

`floorContact` и `spineAssessment` всегда равны `'unavailable'`: эти точки не устанавливают контакт с полом, кривизну или безопасность поясницы. Отсутствие предупреждений не доказывает правильность техники. Результат — приближённая 2D-проекция с учётом размера кадра, без использования Z. Если обе стороны видимы, явно неподходящий ракурс отбраковывается, но строго боковую съёмку автоматически подтвердить нельзя. Закрытые суставы, поворот тела или камеры и ошибки модели влияют на результат; реальное видео пока не проверялось.

При потере нужной точки или смене стороны незавершённая попытка отменяется, счёт сохраняется. `setFrameSize()` также отменяет попытку при любом изменении разрешения. Метод `update()` не получает временные метки и не распознаёт длительные пропуски сам: при перемотке, смене источника или длинной паузе вызывайте `resetTracking()`, даже если разрешение осталось тем же.

## Анализатор подтягиваний

`pullupAnalyzer.js` — отдельный ES-модуль, подключённый к общему интерфейсу. Снимайте спереди или сзади; оба плеча (11/12), локтя (13/14) и запястья (15/16) должны оставаться в кадре. Камера может быть на полу или штативе, но наклон камеры, перспектива и перекрытия искажают измерения. Узкий боковой ракурс отбраковывается приблизительно, а строгая фронтальная или тыловая съёмка автоматически не подтверждается.

```js
import { PullUpAnalyzer, PULLUP_ERROR } from './pullupAnalyzer.js';

const pullup = new PullUpAnalyzer({ maxFrameGapMs: 1000 });
pullup.setFrameSize(video.videoWidth, video.videoHeight); // после загрузки видео, до update

// Вызывайте один раз на обработанный кадр. timestampMs — та же строго
// возрастающая отметка performance.now(), что передана в detectForVideo.
// chinY — надёжная нормированная координата 0..1 от ДРУГОГО детектора;
// если её нет, передавайте null или опустите третий аргумент.
function analyzePullUp(landmarks, timestampMs, chinY = null) {
  const result = pullup.update(landmarks, timestampMs, { chinY }); // при потере позы: null
  const { repCount, currentPhase, currentErrors, feedbackMessage, headReference, barReference } = result;
  if (currentErrors.includes(PULLUP_ERROR.ASYMMETRY)) {
    // Показать текстовую подсказку о равномерной тяге.
  }
  return result;
}

pullup.resetTracking(); // отменить незавершённый цикл, сохранив счёт
pullup.reset(); // начать новый подход с нуля
```

`HANG` требует угол плечо–локоть–запястье строго больше 160° в **обоих** локтях и кисти выше плеч в кадре. `PULLING` — наблюдаемый подъём плеч относительно среднего уровня запястий. `TOP` — ориентир головы строго выше среднего уровня запястий, в том числе при опускании; кроме того, есть `WAITING`, `TURNAROUND` для подтверждённой неполной верхней точки и `LOWERING`. Засчитывается только `HANG → TOP → HANG`. Если подъём начат при угле хотя бы одного локтя строго меньше 145°, появляется «Опускайтесь до полного виса»; старт от 145° до 160° также не считается полным, хотя отдельное предупреждение <145° к нему не применяется. Когда после подъёма верх не достигнут и определён разворот или плато, показывается «Тянитесь выше, подбородок над турником».

Для отсечения мелких движений подъём плеч относительно кистей должен составлять минимум 15% исходной ширины плеч, каждый локоть должен согнуться минимум на 10°, а разворот от вершины — минимум 6% ширины плеч. Начало подъёма фиксируется при 5% ширины плеч; плато оценивается по шести кадрам. После возвращения близко к исходной высоте при всё ещё согнутых руках анализатор ждёт полного виса: если прежде начался новый подъём, прежняя попытка не засчитывается. Это эвристики, а не оценка реальной техники.

По выбору сначала используется внешний `chinY`, затем средняя высота видимых точек рта 9/10, затем нос 0. При одной видимой точке рта она используется приблизительно. `headReference` принимает значения `'external'`, `'mouth'`, `'mouth-single'`, `'nose'` или `'unavailable'`; использование одной точки рта сохраняется в статусе до конца попытки. **Нос и точки рта не являются подбородком:** особенно по носу TOP может быть отмечен, когда подбородок ещё ниже кистей. При съёмке сзади лицо часто не видно; тогда необходимо передавать надёжный `chinY` от внешнего детектора на каждом кадре. Его точность модуль не проверяет. Выбранный источник головы фиксируется на время попытки; при его потере незавершённая попытка отменяется, даже если внезапно появился другой ориентир. Без лица и внешней координаты подсчёт невозможен. В текущем интерфейсе внешний детектор `chinY` не подключён: при скрытом лице подсчёт недоступен.

`barReference` равно `'wrists'`: перекладина не обнаруживается, её горизонтальный уровень приблизительно берётся как средняя Y-координата запястий. Это не доказывает, что подбородок находится над настоящей перекладиной. Ракурс снизу, наклон, разные высоты кистей и перспектива могут заметно изменить результат. По этим точкам также нельзя подтвердить хват, настоящий свободный вис, отсутствие опоры ног или исключить подтягивание с прыжком. Отсутствие предупреждений не означает корректной или безопасной техники.

Асимметрия сравнивает вертикальные скорости обоих плеч относительно среднего уровня кистей в 2D-проекции. В фазе подъёма, если хотя бы одно плечо движется вверх, разница строго более **0,8 исходной ширины плеч в секунду** за окно не менее 200 мс вызывает «Тяните равномерно обеими руками» и сохраняется до завершения попытки. Неподвижная разница высот плеч сама по себе не считается разницей скоростей; шум landmarks, низкая частота кадров и ракурс снижают надёжность. Для сравнения используются окна не длиннее 1000 мс, поэтому при слишком редких кадрах предупреждение может отсутствовать.

Передавайте размеры исходного видео: X и Y масштабируются по разным осям, Z не используется. Если время не передано, используется `performance.now()`; явно переданные отметки должны быть неотрицательными и строго возрастающими между сбросами. Пропуск более `maxFrameGapMs` (по умолчанию 1000 мс), потеря нужных суставов или ориентира отменяет попытку, сохраняя счёт. Смена размера видео также отменяет попытку; при перемотке или смене источника с тем же разрешением вызовите `resetTracking()`. Синтетические тесты проверяют логику модуля; реальное видео пока не проверялось.

## Проверка

```sh
node --test tests/*.test.mjs
```

Браузерные smoke-тесты используют небольшой тестовый WebM, синтетическую камеру и подменяют модель MediaPipe; тесты подходов и упражнений также подменяют Web Audio для проверки вызова сигнала. Эти синтетические тесты не являются проверкой точности упражнений на реальном видео. При желании установите Playwright вне проекта и запустите тест (пример для Linux/macOS):

```sh
npm install --prefix /tmp/motion-playwright playwright
/tmp/motion-playwright/node_modules/.bin/playwright install chromium
NODE_PATH=/tmp/motion-playwright/node_modules node tests/video.browser.cjs
NODE_PATH=/tmp/motion-playwright/node_modules node tests/workout.browser.cjs
NODE_PATH=/tmp/motion-playwright/node_modules node tests/exercises.browser.cjs
```

Если Chromium уже установлен, его путь можно указать через `MOTION_CHROMIUM_PATH`. Файл `tests/fixtures/short.webm` — синтетический тестовый видеоряд, а не пользовательское видео.
